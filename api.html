API

All the data is free to read as JSON, with no key and no sign-up: plain files on https://liftradar.eu, readable from any site (CORS allows any origin). The format is defined by the JSON Schema of each file.

AI assistants can read the same data through the MCP server, also with no key.

For code generators and API tools, every file is described in OpenAPI 3.1.

MCP

https://liftradar.eu/mcp

For AI assistants, the same data is an MCP server, with no key: add the address above as a remote server (Streamable HTTP) in Claude, Cursor or any other MCP client. Its tools find resorts by country, status, snow, open lifts or distance from a point, and read one resort's report, its history and the daily stats.

claude mcp add --transport http liftradar https://liftradar.eu/mcp

All resorts

GET https://liftradar.eu/json/index.json

Every resort with its main values: status, snow depths, open lifts and slopes, avalanche level, location and the groups it's in (schema). Each resort's country and id give the address of its full report.

One resort

GET https://liftradar.eu/json/<country>/<id>.json

One resort's full report (schema): everything in the list, plus snow stations, lifts by type, slopes by difficulty, the avalanche bulletin and the reports it was built from. For example json/at/hintertux.json. The id is in the address of each resort's page on this site.

country is the ISO code in lower case: at, ch, cz, de, es, fi, fr, it, no, pl, si, sk. These addresses stay: when resorts merge, the old ones keep working as copies of the new one's.

curl -s https://liftradar.eu/json/at/hintertux.json | jq '{status, snow: .snow.mountain_cm, lifts}'

History

GET https://liftradar.eu/history/<country>/<id>.json

The key numbers of every run over the last 365 days, one list per value: time, status, open and total lifts and slopes, open km and snow depths (schema). Data has been collected since 24 October 2026.

Stats

GET https://liftradar.eu/json/stats.json

Daily totals per country and region over the last 365 days: resorts tracked and open, and their open lifts, slopes and km (schema).

Resort groups

GET https://liftradar.eu/json/groups.json

The groups of resorts we list separately, by id: ski areas linked by lifts and runs (linked, e.g. Les 3 Vallées) and passes or regions whose areas aren't linked (region, e.g. Dolomiti Superski), each with its name, website and members as <country>/<id> (schema).

Pistes and lifts

GET https://liftradar.eu/ski/v1/10/<x>/<y>.json
GET https://liftradar.eu/ski/v1/resorts.geojson
GET https://liftradar.eu/ski/v1/meta.json

The lifts, pistes and ski areas of OpenSkiData in map tiles (XYZ, zoom 10), each with its resort here when it has one (schema), and each resort's outline and point on the map. The build and counts are in meta.json. Rebuilt weekly, under the ODbL: data from OpenSkiData, © OpenStreetMap contributors.

Reading the values

  • null means the source doesn't publish the value. status is never null: it's open, closed or no_report.
  • With no_report, lifts.open is 0 and slopes.open is null. With closed, the snow depths and condition are null; last_snowfall and station measurements stay.
  • fetched_at is when we read the report and lifts_updated_at is the resort's own report time, null if its source has none. status_from is set when the latest run couldn't read the report, and gives the time of the run the values come from.
  • source_details lists the pages a report was built from: conditions give current values, resort_info only what stays the same (the size of the ski area). attribution_required is true where the source's terms ask for a credit, false where they don't and null where we haven't checked: treat it as true. sources is deprecated: it lists the same pages as plain URLs, and will be removed.
  • linked_area is the id of the ski area a resort shares with others, linked by lifts and runs (les-3-vallees), and ski_region that of the pass or region it shares without a link (dolomiti-superski); look them up in json/groups.json. Both are left out for a resort that isn't in such a group.
  • Times are ISO 8601 with the Central European offset (+01:00, +02:00 in summer). condition is in the source's language.

What the numbers mean, and where they can mislead, is on About the data.

Polling

The data changes twice a day, at about 08:40 and 13:40 CET, so there's no point reading it more often than hourly. The files have an ETag: send If-None-Match and an unchanged file costs nothing. Questions, or a use we should know about: miron [at] liftradar.eu.
